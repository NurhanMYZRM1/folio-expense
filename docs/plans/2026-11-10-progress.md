## 12 November: desktop sign-in fix

The physical-iPhone session (commit `c4bd132`) found desktop Google sign-in stuck on the Google page. Cause: macOS had about twenty copies of Folio registered for `expenseapp://` and chose a stale debug build, and browsers often refuse to open an app link at the end of a redirect. Fixed in `eed3cde`: the desktop now returns to a one-time listener on `127.0.0.1` (RFC 8252). Release app: `src-tauri/target/release/bundle/macos/Folio.app`. Rust 233 passed; Settings browser tests pass. Supabase already accepts the loopback address (Site URL is localhost); adding `http://127.0.0.1:*/auth/callback` explicitly is recommended.

Still open: desktop Google sign-in with the fixed build (needs the owner in the browser), the receipt progress banner on the physical phone (the phone's test profile expires 13 Nov 00:34 MYT), deletion propagation, and the optional second account.
