# Physical iPhone test build

Device: the paired iPhone 17 Pro named **Mn**, running iOS 27.0.1. Installation uses Xcode's existing wireless pairing over the local network. No App Store or TestFlight submission is involved.

## Native setup

`mobile/app.json` enables `expo-build-properties` → `ios.enableSceneSupport`. This SDK 57 option generates the scene manifest and makes the app delegate an `ExpoReactNativeFactoryProvider`. Without it, an app built with this Mac's Xcode 27.2 traps at `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption` on iOS 27 before opening the database. The installed Expo 57.0.26 and build-properties 57.0.22 already support the option; no SDK upgrade was needed.

Regenerate with `npx expo prebuild --platform ios --no-install` and run `pod install` from `mobile/ios`. Keep build products outside the generated `ios` folder, which prebuild may recreate. Rebuild the Rust XCFramework with `npm run rust:ios` before the Xcode build.

The local Apple personal development team cannot provision the remote push entitlement generated by `expo-notifications`. This test build uses an external signing-entitlements file with `aps-environment` removed. This is a local build override; the source app entitlement configuration is preserved for distribution with a suitable developer team. Foreground cloud sync and local reminders do not require remote push.

The replacement uses the Release configuration to bundle JavaScript and its assets into the app. It opens directly without Metro. Signing uses the existing Apple development certificate and a profile that includes the paired phone. The profile expires at **13 November 2026, 00:34 MYT**; a fresh signed installation is needed after expiry.

## Finance screen follow-up

The first standalone build contained the current Finance code, but its screen failed during module initialization: `undefined is not an object (evaluating 'tslib.default.__extends')`. The PDF library's nested `tslib` resolved to a Node ESM wrapper that Metro could not interoperate with. The same failure was reproduced in the simulator and by loading the exact Release Finance HTML/JavaScript in a browser test.

`mobile/metro.config.js` now resolves bare `tslib` imports to the pure ESM helper entry. `tslib` 2.8.1 is a pinned direct mobile dependency. The regression loads Metro's built output with the native DOM message protocol and a disposable Rust database, rather than testing the desktop Vite output. No hosted data or real credentials are used. One test verifies the Overview → native Finance handoff; another opens all eight Finance sections. The latter failed before the resolver fix; both pass after rebuilding.

Run these checks against a completed native build:

```sh
FOLIO_DOM_BUNDLE=/path/to/Folio.app/www.bundle npm run test:e2e -- mobile-dom
```

The tests skip when that environment variable is absent. Mobile typecheck and lint also pass, with the same two existing lint warnings. The user deferred further physical interaction; simulator/bundle verification continues independently.

The final corrected bundle passes both regression tests and the simulator displays Finance overview successfully. Wireless installation of this correction was attempted, but the physical phone became unavailable (`CoreDeviceError 4016`); **the phone still has the earlier Finance-loading bug until this build is installed**.
