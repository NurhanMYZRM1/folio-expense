# Launch audit: privacy, transparency, accessibility

Audit date: 5 November 2026, against `main` at `126d459` plus the changes listed below. **This is an engineering audit, not legal advice.** Adding these policies does not make Folio legally compliant; the items under [Legal review](#items-for-legal-review) must be settled by a qualified Malaysian lawyer.

## What Folio is (verified in code)

- **Platforms:** Tauri 2 desktop app (macOS, Windows) and an Expo SDK 57 iPhone app (`mobile/`). Both run the same Rust core (`src-tauri/`) and the same React screens (`src/`).
- **Users:** individuals and employees preparing expense claims. The receipt reading is tuned for Malaysian receipts (MYR default, Malay labels, Malaysian postcodes).
- **Accounts and authentication:** none. No sign-in, cloud sync or backend operated by the publisher.
- **Storage:** SQLite and receipt files in the platform app-data folder (`expense-app/`); the optional AI API key in the OS credential vault (`src-tauri/src/security/secrets.rs`).
- **Network:** exactly three flows. (1) Frankfurter exchange rates, on by default (`src-tauri/src/services/exchange_rates.rs`). (2) Online AI extraction to a user-configured HTTPS endpoint, off by default (`src-tauri/src/services/extraction/online.rs`). (3) iOS only: Expo EAS Update check at launch (`mobile/app.json` `updates.url`).
- **Analytics, ads, crash SDKs, cookies, payments, subscriptions, marketing messages:** none. Searches of `src/`, `src-tauri/src/`, `mobile/src/` and the dependency manifests found no such SDKs or code. The desktop CSP (`src-tauri/tauri.conf.json`) blocks remote scripts and connections.

### Not applicable, with evidence

- **Refund and cancellation policies, price/trial/renewal disclosure, hidden fees:** there is no payment, purchase, subscription or trial code. Add these before charging.
- **Cookie policy and consent banner:** no cookies, local/session storage, trackers or analytics. The only web content is bundled into the app, and there is no website. Revisit if you build a marketing site.
- **Marketing consent, unsubscribe:** Folio collects no contact details and sends no messages.
- **Account deletion (Apple 5.1.1(v)):** no accounts.
- **Misleading urgency, fabricated reviews, unsupported claims:** none found. In-app claims ("No account required", "Saved on this device", "Online extraction is optional", "Disabled by default") match the code.
- **Optional permissions preselected:** online AI is off by default. Camera and photo access are requested by iOS only when used, with purpose strings in `mobile/app.json`. Conversion defaults on (finding 13).
- **Age verification:** Folio is an expense tool, not directed at children. It has no accounts and collects nothing centrally, so adding age checks would only collect extra data. Answer Apple's age-rating questionnaire honestly (no user-generated content, web access or purchases), and do not list it in the Kids category.

## Jurisdiction (Malaysia), verified sources

**Personal Data Protection Act 2010 (Act 709), as amended by Act A1727 (2024).** Applies to anyone who processes, or controls or authorises the processing of, personal data "in respect of commercial transactions" (s.2(1)), if established in Malaysia (s.2(2)). It exempts data processed by an individual only for "personal, family or household affairs" (s.45(1)). The notice must be "in the national and English languages" (s.7(3)). The amendments commenced in three stages (1 January, 1 April and 1 June 2025). They introduce data protection officers, breach notification (Commissioner within 72 hours, affected individuals within 7 days where there is significant harm, per the 2025 Guideline), and the removal of the cross-border transfer whitelist.

**What this means for Folio (engineering view, for the lawyer to confirm):** the publisher does not receive receipts, expenses or claims, so most PDPA duties attach to whoever controls that data. That is the user, or an employer that deploys Folio. The publisher's possible personal-data processing is the Expo update check (pseudonymous install ID plus IP, handled by Expo). Online AI sends images abroad, but on the user's instruction, with the user's own key, to a provider the user chose.

**Consumer Protection Act 1999 and the Consumer Protection (Electronic Trade Transactions) Regulations.** These require online suppliers to disclose their business name, registration number and contact details, among other information. A 2024 version replacing the 2012 Regulations is reported in operation from 25 December 2024; I did not read its text. Whether a free app listed on an app store falls within them is for the lawyer.

**Accessibility:** I found no binding Malaysian digital accessibility requirement for private-sector apps. A 2021 proposal for WCAG-based guidelines exists. Treat WCAG 2.2 AA as recommended practice.

**Other jurisdictions:** not assessed. Nothing in the code or docs names markets beyond Malaysia. If you publish on the App Store worldwide, decide the target countries first; the Expo data flow is then the main item to re-check (for example under the GDPR).

## Verification

- `npm run test:rust`: 167 passed, including the new `erase_all_data_leaves_an_empty_workspace_and_no_trace_of_records`. It refuses while a job is running, and checks that a unique string is on disk before the erase and absent from the database and WAL after. `npm test` 40 passed. `npm run build`, `npm run lint` (no new warnings), `npm run lint:rust`, `cargo clippy --features mobile`, `npm run format:check`: all pass.
- **Accessibility, tested on the running UI** (Chrome, Vite build, real Rust core through the test driver, a real imported receipt run through OCR, plus a manual expense and a claim). axe-core 4.10.3, WCAG 2.0/2.1/2.2 A and AA rules, on 8 screens × light/dark × 1440 px/390 px. Before: 1 rule failed (finding 8). After: 0 violations on all 32 variants. A keyboard walk through Overview, Settings and the expense editor found a visible focus indicator at every stop and a logical order. The erase dialog takes focus on Cancel, Escape closes it and returns focus to its button, and confirming emptied the workspace and its receipt folder. Reflow at 320 px: no page scrolls horizontally. Non-text contrast was computed from the CSS tokens. Reduced motion: `MotionConfig reducedMotion="user"` and a CSS `prefers-reduced-motion` block were already in place.
- **Not tested:** VoiceOver or NVDA with real use; iPhone native screens (`mobile/src/native/`) and Dynamic Type; Windows; 1.4.12 text spacing; an iOS build with the new privacy manifest (it changes the fingerprint, so it needs `eas build`, not `eas update`).

## Outstanding decisions and configuration

1. **Your facts for the policies:** legal name, SSM number (if a business), postal address, contact email, price (free?), distribution channels, target countries.
2. **Host the privacy policy and terms** at a public URL, enter it in App Store Connect, and add an in-app link. Opening an external URL needs new plumbing (the desktop renderer has no opener permission; iOS can use `expo-web-browser`), so I did not add a link that would lead nowhere.
3. **Expo:** confirm what EAS Update retains, and answer App Store "App Privacy" from that (likely Identifiers → Device ID, used for App Functionality, not linked to identity, no tracking).
4. **Disk-space required-reason API:** `statfs`/`fstatfs` most likely come from bundled SQLite's file-system checks, which match no Apple reason. Options: build SQLite without that check, or wait for Apple's ITMS-91053 email after the next upload and decide then. Do not declare a reason that is not true.
5. **Export compliance** answers for rustls (finding 14).
6. **Licence notices** for all bundled crates and packages (finding 11).
7. **Default for currency conversion** (finding 13).
